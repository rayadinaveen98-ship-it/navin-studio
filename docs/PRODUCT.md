# Product brief — NAVIN STUDIO

**Version:** 0.1 (2026-11-08)  
**Status:** Working brief; name and visual direction awaiting owner approval.

## Mission
Create a premium, fast, evolving digital home for a small independent studio that makes apps, games, films, educational experiences and stories. Public visitors discover and genuinely experience released work. The studio owner sees accurate progress and release status in a secure private command center.

## Audiences
- **Visitors:** See public creations, explore features, try published demos, access approved downloads and learn what changed.
- **Studio owner:** Review release candidates, approve public updates, monitor milestones, see verifiable build/QA evidence and manage publishing.

## Public MVP
1. **Studio Home:** clear creative identity, featured project, curated categories, release announcements.
2. **Explore:** filter by Apps, Games, Film, Stories, Learning, and Interactive; show only approved public entries.
3. **Project Page:** purpose, screenshots, supported platforms, links, actual release status and development journal.
4. **Release Center:** stable and beta channels separately; version, release date, what's new, download URL, SHA-256 where available, upstream source.
5. **Experiences:** launch actual web experiences only if a working embed or hosted build exists.
6. **Responsive & accessible:** mobile/desktop and touch/keyboard parity; reduced motion mode and legible typography.

## Private work (not MVP)
- Secure owner-only authentication/authorization, never a CSS-hidden public dashboard.
- Milestones, QA, release approval and revision history.
- Aggregate analytics from legitimate authorized sources, not estimates.
- Source-linked studio assistant only after reliable access boundaries and costs are confirmed.

## Non-goals for MVP
- No rewriting the existing apps or games.
- No pretending incomplete products are ready to download.
- No automated public release without a manual approval decision.
- No public exposure of private repositories, tokens, workspace notes or unpublished APKs.
- No paid services by default.

## Visitor journeys
**Discover:** Home → category → project → official experience or release.  
**Update:** Home update tile → release detail → changelog + provenance → verified download.  
**Explore:** Browse → filters → project page → published demo when available.

## Acceptance criteria
- No misleading “verified”, “released”, “new” or percentage values.
- No broken “Download” buttons; hide unavailable actions instead.
- Empty states explain “No public release yet”.
- Slow network, missing releases and API limits degrade gracefully.
- Accessibility keyboard audit and mobile layout review before launch.
- User approves high-fidelity design references before frontend implementation.

## Brand ownership
NAVIN STUDIO is a **working proposal**, not a locked trademark or final brand. Each project retains its own visual identity within a coherent studio shell.
